# Test Plan – Supmedic Website

## 1. Introduction
This test plan describes the testing strategy, scope, approach, and resources for manual testing of the Supmedic medical company website.  
The goal of testing is to ensure that the website meets functional, usability, and quality requirements.

---

## 2. Project Overview
- Project: Supmedic medical company website
- Website: https://supmedic.by
- Testing type: Manual testing
- Testing method: Black-box testing
- Platform: Web application

---

## 3. Objectives
The main objectives of testing are:
- Verify correct functionality of the website
- Identify defects affecting user experience
- Ensure usability and navigation clarity
- Validate cross-browser and responsive behavior
- Confirm that content meets business requirements

---

## 4. Scope of Testing

### In Scope
- Functional testing of website features
- UI testing (layout, fonts, buttons, images)
- Usability testing
- Cross-browser testing
- Cross-platform and responsive testing
- Regression testing
- Content verification

### Out of Scope
- Backend testing
- Security testing
- Performance testing (except basic observations)
- API testing

---

## 5. Test Items
- Main page
- Header and footer navigation
- Forms and input fields
- Buttons and links
- Content sections
- Responsive layout elements

---

## 6. Test Approach
Testing will be performed manually using black-box testing techniques.  
The following testing types will be applied:
- Functional testing
- UI testing
- Usability testing
- Regression testing
- Cross-browser testing
- Responsive testing

Test cases, checklists, and bug reports will be created during testing.

---

## 7. Test Environment
- OS: Windows 10
- Browsers:
  - Google Chrome
  - Mozilla Firefox
  - Safari
  - Microsoft Edge
  - Opera
  - Yandex Browser
- Devices:
  - Desktop
  - Tablet
  - Mobile (via browser responsive mode)

---

## 8. Entry Criteria
Testing can start when:
- Website is deployed to test or staging environment
- Requirements are available
- Test environment is accessible

---

## 9. Exit Criteria
Testing is considered complete when:
- All planned test cases are executed
- Critical and high-priority defects are fixed or documented
- Test summary report is prepared

---

## 10. Test Deliverables
- Test plan
- Test cases
- Test checklists
- Bug reports
- Test summary report

---

## 11. Risks and Assumptions

### Risks
- Limited test environment access
- Changes in requirements during testing
- Time constraints

### Assumptions
- Requirements are clear and stable
- Test environment reflects production behavior
- Stakeholders are available for clarification

---

## 12. Roles and Responsibilities
- QA Engineer:
  - Test planning
  - Test execution
  - Bug reporting
  - Documentation

---

## 13. Tools
- Browser DevTools
- Jira (for bug tracking)
- Google Docs / Microsoft Word (documentation)

---

## 14. Approval
This test plan is reviewed and approved by the project stakeholders before testing execution.
